# prisma-nextjs-blog — risks and open questions

| ID | Risk | State | Notes |
|---|---|---|---|
| PR-A | `baseline-v1` is not yet proven live | OPEN | Proven offline in Baseline CI: the offline bootstrap with the blueprint's own hooks, the lanes' own steps in staged job trees (the migrations applied through a stand-in Supabase Management API over a real Postgres with Supabase's roles), and the built Worker served by `wrangler dev` over it. A live bootstrap needs a workspace with Cloudflare and Supabase connected and room for two Supabase projects (PR-E) |
| PR-B | The Worker's size | ACCEPTED | About 2.6 MiB gzipped, under Workers Free's 3 MiB; Prisma's query compiler (3.4 MB raw) is most of it. A larger schema grows it little; another heavy dependency could cross the line and need Workers Paid |
| PR-C | next-auth 4 on Next.js 16 and workerd | ACCEPTED | next-auth 4.24.15's peer range admits Next 16. Its OAuth exchange (openid-client over `node:http`/`https`) ran on workerd in the spike against a stand-in for GitHub; `tests/web` drives its options and the e2e serves its database sessions. A real GitHub sign-in is PR-A |
| PR-D | Two migrations per schema change | ACCEPTED | Prisma's (`apps/web/prisma/migrations`, for local databases) and db-migrate's (`packages/db`, deployed). tests/db fails when `010_blog` stops being upstream's migration or what `prisma migrate diff` writes for `schema.prisma` |
| PR-E | Two Supabase projects per product | ACCEPTED | Stage and prod are a project each; the free plan allows two active projects per organization. BOOTSTRAP.md lists it as a prerequisite |
| PR-F | Upstream let any writer publish or delete any post | RESOLVED | `lib/own-post.ts`: 404 for a missing post, 403 for someone else's; `tests/web` and the e2e hold it |
| PR-G | Hyperdrive's read cache | RESOLVED | Off in the `cloudflare-hyperdrive` root: the blog reads its own writes at once. Connections are still pooled |
| PR-H | The cookie secret lives in the database | ACCEPTED | Generated by `030_app_secrets` in `app_private`; whoever can read the database can forge a CSRF or state cookie (sessions are database rows, so not a session). A `SECRET` Orun secret overrides it |
| PR-I | The webpack externals rule depends on Prisma's import spelling | ACCEPTED | It keeps any `*.wasm?module` request for wrangler. If Prisma changes how the `workerd` client loads its compiler, the build or the e2e fails, not the deploy |
